## 3. Exact Gate Call Path and Ordering Proof

### Call Path

```text
main(argv)
  │
  ├── Parses CLI args ("build" or "ic1", --root, --work, --variant, --manifest-out, --out)
  │
  └── run_gated_build(root, repo, work, command, variant, committed_manifest, manifest_out)
        │
        ├── [Step 1: R-1 Manifest Gate]
        │     check_manifest_gate(root, committed_manifest)
        │       ├── regenerate_manifest(root)  ──> [bwrap entries 1 & 2: find & sha256sum]
        │       ├── SHA-256 digest comparison
        │       └── exact byte comparison (matches == True)
        │           └── On failure: raises ManifestGateError (STOPS IMMEDIATELY)
        │
        ├── [Optional: write gate.regenerated_bytes to manifest_out]
        │
        ├── [Step 2: Checkout Preparation]
        │     work.mkdir()
        │     prepare_checkout(repo, co, touch_time=touch)
        │
        └── [Step 3: R-2 / IC-1 Entry]
              build(root, co, variant, trace_dir, strace) ──> [bwrap entry 3: build.sh / IC-1]
```

### Ordering Proof

1. In `run_gated_build`, `check_manifest_gate(root, committed_manifest=committed_manifest)` is the **first statement**. If it fails or raises `ManifestGateError`, execution halts immediately. `work.mkdir`, `prepare_checkout`, and `build` are never reached.
2. In `test_rp11_launch_gate.py::test_ordering_is_strictly_enforced`, function calls are recorded into a spy list:
   `call_log == ["regenerate_manifest", "prepare_checkout", "build"]`
   The test asserts that this exact sequence is deterministically followed.
3. In `test_rp11_launch_gate.py::test_gate_refuses_on_one_byte_drift` and `test_gate_refuses_on_manifest_regeneration_failure`, mock assertions verify that `prepare_checkout.called` and `build.called` are both `False`.

- **Withdrawal of Causal Explanation Claims:** The prior claim that regex rules could verify causal explanations is completely withdrawn. A regex match is not causal evidence under LD-8.
- **Conservative Byte-Level Analysis:**
  - Implemented `compare_cc1_v(baseline_bytes, actual_bytes) -> CC1ComparisonReport`.
  - Reports SHA-256 for both streams.
  - Computes exact differing byte offsets (`baseline_offset`, `actual_offset`), lengths (`baseline_length`, `actual_length`), and raw byte values (`baseline_bytes`, `actual_bytes`).
