## 3. Producer-mapping semantics, before and after

| Row | Field | Before (R3) | After (R4) |
|---|---|---|---|
| **S4-3** | `in_harness_producer` | `True` (because `schema is None`) | **`False`** (no step produces it) |
| | `producer` | "this harness's own generated steps" | "none — no producer exists: no step of this plan produces this case, no reviewed external producer supplies it, and the plan declares it unresolved under C-S4-3" |
| | `collection_procedure` | "the executor records the step's observation directly" | "none — there is no collection procedure to run while no producer exists, and a supplied observation cannot stand in for one" |
| | `produced_by_plan_steps` | `()` | `()`, unchanged |
| | `declared_unresolved_by` | `("C-S4-3",)` | `("C-S4-3",)`, unchanged |
| **3 capability cases** | all fields | `True`, harness text, steps, `()` | **unchanged**: produced by steps, so the harness text is true |
| **3 Band-7 cases** | all fields | `False`, schema producer and procedure, `()`, `("C-7",)` | **unchanged** |

**Why no new field.** The prompt permits a typed change only if the existing
vocabulary cannot honestly express *required, unresolved, producer absent*. With
attribution-derived `in_harness_producer`, S4-3's row is `False` / `()` /
`("C-S4-3",)`, and its text names no producer. Every field is true. What sets
S4-3 apart from the Band-7 rows is text: those rows *describe* a future external
producer and an input contract, while S4-3's names none. It is not a Boolean. I
did not add a `producer_state` enum. It would have been a new persisted field,
an artifact-schema bump and a new consumer contract. That is more than the
finding requires. Whether reviewers want that structural distinction is §13
item 1.

**The partial capture.** The `systemctl show` capture step carries
`evidence_case_ids=()`. Its step ID does not appear in S4-3's
`produced_by_plan_steps` or in the producer text, and the text names no step,
path or `systemctl` at all.
